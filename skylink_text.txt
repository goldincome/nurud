1. Introduction & Overview
SkyLink is the 247Travels unified flight integration API. It provides your platform with access to live flight inventory,
real-time pricing, and instant booking — all through a single, clean REST interface. You do not need to integrate
with any airline or GDS system directly; SkyLink handles all of that for you.
Feature
Detail
Protocol
HTTPS REST — JSON request and response bodies
Authentication
JWT Bearer Token (Authorization header)
Search Modes
Local database · Live external inventory
PNR Generation
Instant order creation — no manual ticketing queue
Currency
Multi-currency support
Passenger Types
Adults · Children · Infants
Trip Types
One-way · Round trip · Multi-city
2. Authentication
All SkyLink API endpoints require a valid JWT Bearer token obtained from POST /api/login. Include the token in
every request header.

5. Flight Search
The search endpoint returns available flight offers for your requested route. Use search_mode=local to query our
internal flight database, or search_mode=external to query live airline inventory in real time.
POST
/api/flights/search
Search Available Flights
Returns a list of available flight offers. Each result contains a booking_token required to call the pricing and
reservation endpoints.

Example Request — Multi-City
For multi-city, only the routes array is required. You do not need to pass from, to, or flights_departure_date — the
system automatically derives the origin from the first leg, the destination from the last leg, and the departure date
from the first route date. A minimum of two legs is required.
{
"search_mode": "external",
"flight_type": "multicity",
"adults": 1,
"children": 0,
"infants": 0,
"class": "economy",
"currency": "NGN",
"routes": [
{ "from": "LOS", "to": "LHR", "date": "2026-06-20" },
{ "from": "LHR", "to": "JFK", "date": "2026-06-27" },
{ "from": "JFK", "to": "LOS", "date": "2026-07-05" }
]
}
✓ Origin, destination and departure date are resolved automatically from the routes array. In this example the system
derives: origin = LOS, destination = LOS, departure = 2026-06-20.

6. Flight Pricing
The pricing endpoint re-validates a selected flight offer in real time against the live supplier system. It confirms the
current price, detects changes since the search, and returns an updated booking_token with refreshed offer IDs.
POST
/api/flights/pricing
Verify & Reprice Flight Offer
Confirms availability and current price. Always call this immediately before /api/flights/reserve. Returns
updated booking_token with current offer state.

7. Flight Reservation (PNR Generation)
The reservation endpoint creates a confirmed PNR immediately. Your PNR is returned in the response as soon as
the airline confirms the order.
Payment Responsibility Notice
SkyLink API integration partners are required to collect full payment from their end users prior to calling this
endpoint. The /api/flights/reserve endpoint does not enforce or process payment — it immediately generates a
live airline PNR upon request. Calling this endpoint without prior payment collection constitutes a violation of the
SkyLink API Terms of Service and may result in immediate suspension of API access, recovery of outstanding
amounts, and legal action where applicable. 247Travels reserves the right to audit reservation activity and
enforce accountability at its sole discretion.
POST
/api/flights/reserve
Generate PNR — Create Flight Order
Submits passenger details and offer data to the supplier to create a confirmed flight booking. Returns the
PNR reference immediately.

7.2 PNR Restrictions
SkyLink supports three levels of PNR restriction. When triggered, the endpoint returns HTTP 403 with blocked: true
before any supplier call is made.
Level
Scope
Description
1 — Supplier block
Entire supplier
All reservations via that supplier are blocked.
2 — Carrier block
Specific airlines
Named carrier codes are blocked under that supplier.
3 — Carrier whitelist
Specific airlines
Only listed carrier codes are permitted.
{
"success": false,
"blocked": true,
"carrier": "KQ",
"message": "KQ reservations are not available at this time."
}

8. Workflow Integration Guide
A complete flight booking follows four sequential steps. Each step returns data required by the next — never skip a
step.
Step 1 — POST /api/flights/search
Search with search_mode=external. Returns results with booking_token per flight.
    ↓
Step 2 — POST /api/flights/pricing
Send booking_token. Returns updated booking_token with current pricing.
    ↓
Step 3 — POST /api/flights/reserve
Send booking_token + passenger details. Returns confirmed PNR immediately — no payment step required.
■ Never reuse a booking_token across multiple reserve calls. The token is marked used=1 after a successful reservation.
Always get a fresh token via search → pricing for each new booking attempt.
Important — Payment Obligation
Integration partners must ensure that end-user payment is fully collected and confirmed on their own platform
before calling /api/flights/reserve. This endpoint generates a live airline PNR immediately and unconditionally
upon every valid request. Generating PNRs without prior payment collection is a breach of the SkyLink API
Terms of Service and may result in suspension of API access and recovery of all costs incurred by 247Travels.

Price immediately before reserve
Call /pricing within 5 minutes of /reserve to minimise expiry errors.
Store invoice_id immediately
Save the invoice_id from /reserve before redirecting to payment_url.
Store PNR on receipt
Save the PNR from the status endpoint as soon as has_pnr is true.
Poll status sensibly
Poll /status every 5–10 seconds for up to 5 minutes after payment. Stop on has_pnr or error.
Handle 502 gracefully
Implement user-friendly messaging and a re-search flow for supplier errors.
Refresh tokens proactively
The access_token expires in 15 minutes. Refresh before it expires to avoid mid-flow 401 errors.
